## 1. 目标与已确定边界

- 以 Fork 的源码、`LICENSE.md`、`net.simplyrin.bungeefriends` 包名和核心入口 `Main` 为基础，挑选修改版的功能与优化移植，保留原作者 SimplyRin 的署名。核心插件 `plugin.yml` 作者写为 `SimplyRin, 5H11P`。不提供 `net._5h11p` 包名兼容层。
- 六个模块纳入最终目标：Bungee 核心、Bungee API、Spigot API、三个 Spigot 示例。核心现为单模块 Maven 项目，改造为多模块构建时需保持原插件的身份和已有公开调用路径。
- 单 Bungee 代理、Java 8、现有 1.16 系列服务端。内置语言只保留中文与英文。MySQL 采用修改版的多表结构；不做原版 `main` 表或 YAML 历史数据的自动导入，YAML 文件存储模式继续可用。
- 每阶段独立变更、单独验收并记录构建/测试/人工验证证据。只在对应阶段修复阻塞迁移、数据丢失或越权的缺陷；一般性代码整理进入待办，避免扩大阶段边界。
- 当前没有可用的真实 Bungee/Spigot/MySQL 联调环境，也没有 Docker。自动化验证可以先完成，但真实服务端、数据库和跨服联调是 P7 发布前的必需关口。

| 领域 | Fork 基线 | 修改版待筛选能力 | 迁移重点 / 规模 |
| --- | --- | --- | --- |
| 构建与身份 | 单 Maven JAR，核心入口 `Main`，包名 `net.simplyrin` | 六模块 Reactor，核心入口 `CorePlugin`，`net._5h11p` 包名，API 独立 JAR | 高：恢复原有入口、包名、依赖与产物声明，避免替换原作者身份 |

| 存储 | 原版以 `main` 键值表为主 | `bungeefriends_data`、好友、屏蔽、请求、组队成员、组队请求、好友前缀等多表 | 很高：键映射、NULL、写入顺序、索引、事务及停机刷盘均需验证 |

这属于**大型迁移**：不是简单合并文件。Fork 当前约 67 个非构建文件，修改版当前约 87 个非构建文件；修改版 Git 中还有大量未提交的包名迁移/示例拆分。这里的数量只说明规模，不等于改动行数或已经验证的功能数。预计主要工作集中在 P3–P6，具体工时应在各阶段完成差异清单后再定。

### 优先核查的代码问题

1. **数据完整性（阻塞）**：修改版 `tools/MySQL.java` 的键到多表映射需要逐项审查，尤其状态字段、SQL `NULL` 与字符串 `"null"`、失败返回值和部分写入。`CorePlugin` 的异步写入队列在停机时只等待 10 秒，需验证未完成写入的处理。原版 MySQL 存在拼接 SQL 的做法，不能作为新实现沿用。
2. **并发与资源**：命令、事件和组队/好友过期逻辑中有多个 `sleep` 延迟任务；检查线程池饱和、重复任务、取消和关闭路径。数据库断线重连需避免无界递归或同步阻塞事件线程。
3. **跨服命令越权（阻塞）**：修改版 Bungee API 的 `executeCommand` 当前仅检查目标在线且在某个队伍；必须核实请求发起者仍是目标所在队伍的队长，并确认目标同队。队长切服后也要能通过代理端权威状态完成校验；即时发送与延迟补发不得重复执行。
4. **API 结果与生命周期**：Spigot `SpigotFriendsAPI` 的部分方法把响应当成 `Map`，其他方法却接收解包后的 `data`；队员列表和好友关系等需按实际协议验证。Future 超时、玩家下线、插件停用以及请求取消要有确定终态。
5. **Java 8**：`PartyCmdSenderListener` 使用 `List.of`（Java 9 API）；各模块按 `--release 8` 或等效检查，并核查 JAR 的 Java class 版本。
6. **许可与署名**：Fork 根许可文本是 LGPL 2.1；部分原文件头写 LGPL v3，修改版根许可/构建元数据也改为 LGPL v3。迁移不自动重写既有文件头或宣称解决许可差异；P1 建立文件级清单，发布前据来源和贡献核实许可表述。
