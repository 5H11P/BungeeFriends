# P4 核心功能阶段总结

状态：代码已迁入并通过核心源码编译及有限自动测试；真实代理端行为尚未验收。

## 已实现

- 好友：请求时间和超时检查、待处理请求列表、私有备注、好友建立时间、批量移除及强制添加；好友列表默认分页与隐身显示已修正。`/block`、`/ignore` 沿用旧屏蔽数据，保留 `/friend ignore`。
- 状态：`/status` 支持在线、离开、忙碌和隐身；状态持久化到两种存储。离线、功能关闭和插件停用时取消状态提示任务；隐身玩家不会向好友发送上下线通知。
- 组队：邀请时间/人数上限、设置中的全员邀请/静音/私有、离线踢人、成员权限检查与整队关系事务；`/pl` 是列表别名。离队后组队聊天不再向旧队伍发送。
- 聊天：`/ac`、`/achat` 及 `/chat` 频道切换；Staff 发送和接收均校验权限，补齐中英文消息键。
- 传送：手动 `/party warp` 与队长切服跟随使用可取消任务。执行前复核队长、成员、目标服、服务器过滤和插件状态；重复启动会取消旧任务，配置重载及停机取消挂起任务。可按游戏服务器成员快照二次确认，核心侧投递 `PartyWarpEvent`。
- 资源：核心打包配置只内置中英文；`available.yml` 仅列出中英文，旧语言选择回退英文。保留 `Main`、包名及 `BungeeFriends.getAPI()` 调用入口。

## 接口约定

原有 `BungeeFriends.getAPI().getFriendUtils(UUID)` 和 `getPartyUtils(UUID)` 继续返回原工具对象；它们对未知 UUID 可创建数据，对未启用组队功能的调用不保证可用。存储读写是同步操作，SQL 失败以 `IllegalStateException` 传播；调用者不能把失败当作空列表。公开工具对象可能访问在线玩家和代理状态，宿主插件应在 Bungee 允许访问玩家状态的上下文调用，不应从 Bukkit 主线程跨端直接调用。跨端公开 API 属 P5 范围。

`PartyWarpEvent` 是一次已排定传送的代理端事件，包含独立 warp ID、队长、目标服、触发来源和不可修改的成员快照。事件经有界异步池投递；监听器不得假设调用发生在 Bukkit 主线程，也不得把事件视为每位成员已成功切服的确认。队伍在事件投递前被取消时不会投递；成员执行时仍会重新检查在线和队伍关系。
